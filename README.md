# Vert.x template

Provisioned from [`Qode-Fleet-Control/fleet-template-v1`](https://github.com/Qode-Fleet-Control/fleet-template-v1) — the fleet
lifecycle contract (`bin/`, `fleet.conf`, deploy workflows) with a
Eclipse Vert.x starter laid on top.

Vert.x 5.2 on Java 21, Maven build, with Vert.x Web: `MainVerticle` routes `GET /` (a small JSON document) and `GET /health`, packaged as the generator's shaded fat jar.

## Run it

**On the fleet** — nothing to do: the fleet clones the repo, injects `PORT` (plus
`DATABASE_URL` and the workspace's other services) and calls `bin/run`, which runs
fleet.conf's `DOCKER_BUILD_CMD` (`docker compose build`) then `DOCKER_START_CMD`
(`docker compose up`, in the foreground). The health check hits `/health`.

**With docker**, locally:

    PORT=8888 bin/run                  # the fleet's docker runtime
    docker compose up --build            # or plain compose; serves on ${PORT:-8888}
    curl http://localhost:8888/health

**Without docker** — a JDK 21 on `PATH`; `./mvnw` (the generator's Maven wrapper) fetches Maven itself:

    FLEET_RUNTIME=process PORT=8888 bin/run

| step | command |
|---|---|
| install | `./mvnw -B -q dependency:go-offline` |
| build | `./mvnw -B -q package -DskipTests` |
| start | `env PORT="$PORT" java -jar target/app-1.0.0-SNAPSHOT-fat.jar` |

    ./bin/run       # install, build, start in the foreground
    ./bin/start     # start from existing build artifacts
    ./bin/restart   # rebuild and restart
    ./bin/stop      # stop whatever holds the port

## Serving

Listens on `0.0.0.0:$PORT` (default `8888`), read from the environment at run
time. The app is served at the root (`/`) of its own hostname
(`https://<hash>.<FLEET_APP_DOMAIN>/`), so every route, redirect and asset URL is
a plain root path. `/health` answers 200 for the fleet's health check.

## Layout

- `src/main/java/world/qode/app/MainVerticle.java` — the router and HTTP server, port from `$PORT`.
- `src/test/java/world/qode/app/TestMainVerticle.java` — generated deploy test plus a `/health` test.
- `pom.xml` — stock; builds `target/app-1.0.0-SNAPSHOT-fat.jar`.

## What differs from stock output

- `MainVerticle`: stock output answers every request with plain text on a hard-coded port 8888; this one uses a Vert.x Web `Router` (`/` and `/health`) and listens on `0.0.0.0:$PORT` (default 8888).
- `TestMainVerticle`: added a `/health` test.
- `README.adoc` folded into this file (below).
- `.gitignore`: dropped the stock Eclipse `bin/` entry (it would ignore the fleet's `bin/` scripts) and appended the fleet entries.
- Added the fleet harness: `bin/`, `fleet.conf`, `Dockerfile`, `compose.yaml`, `.dockerignore`, `.github/workflows/`, `docs/fleet-lifecycle.md`.
